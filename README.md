# sp_stage2：第二阶段底盘与云台

本仓库存放第二阶段两块C板的独立固件：`chassis/`为麦轮底盘，`gimbal/`为云台、测距与轨迹跟踪。两者分别编译、分别烧录，通过CAN2通信。

第一阶段代码单独保存在[sptest仓库](https://github.com/heigangrusy-dot/sptest)。本仓库当前目录不混放第一阶段独立工程；开发历史保留原有提交，因此仍可追溯到早期基础代码。

## 开发、编译与烧录

使用STM32CubeCLT提供的ARM GCC、CMake和Ninja，VS Code可配合CMake Tools与Cortex-Debug使用。本次底盘验证工具链为ARM GCC 14.3.1。

在已经配置工具链环境变量的终端分别执行：

```powershell
# 底盘：从仓库根目录开始
cd chassis
cmake --preset Debug
cmake --build build/Debug
```

```powershell
# 云台：从仓库根目录开始；先补齐上文所述依赖
cd gimbal
cmake --preset Debug
cmake --build build/Debug
```

输出文件分别为`chassis/build/Debug/sptest.elf`与`gimbal/build/Debug/RM_stage2.elf`。`build/`属于本地生成文件，不纳入提交。

使用VS Code调试时，分别打开`chassis/`或`gimbal/`目录，让各工程内的`.vscode`、CMake预设和OpenOCD配置生效。将对应固件烧录到对应C板，不能将两个工程链接成一个固件或混烧。

本交付目录已包含中间件源码快照，不依赖额外初始化子模块；原始历史中的版本可能仍使用子模块。

## 底盘硬件与操作

| 接口 | 当前用途 |
| --- | --- |
| CAN1 | 四台M3508/C620，以及0x301功率计 |
| CAN2 | 向云台发送0x111板间状态报文 |
| USART1 | 绘图串口，921600、8N1 |
| USART3 | DT7遥控接收，100000、9位字长、偶校验 |
| USART6 | PM02学生串口，115200、8N1；PG14为TX，PG9为RX |
| 底盘BMI088 | IMU姿态估计与航向保持，C板固定在底盘 |

轮位ID：右前1、左前2、左后3、右后4。轮半径0.077m，半轮距/半轴距对应0.185m/0.165m；减速比使用导师确认的13.7。速度反馈统一为轮侧rad/s，命令转矩为轮侧N·m。

右拨杆功能：

| 档位 | 底盘行为 |
| --- | --- |
| 下档 | 禁止转矩输出；停稳、反馈及IMU就绪后，为下次自动运行重新准备 |
| 中档 | 左摇杆控制前后与横移，拨轮控制旋转，保留航向保持 |
| 上档 | 执行一次编码器测距自动直行，接近终点减速，停稳后置完成标志 |

上电先保持下档、静止等待IMU约2秒校准，并确认遥控、四轮反馈、PM02上限正常。上档自动运行不重复起跑，再次运行需回下档停稳。自动过程中下档失能；切中档退出本次自动并进入手动控制。

**当前参数快照是后退，不是最初的前进3.5m：**`AUTO_DISTANCE_M=-3.8m`、`AUTO_SPEED_MPS=-0.9m/s`。负号代表后退，距离与速度须同号。自动加速度0.8m/s²、减速度1.0m/s²，终点容差0.02m，停稳确认200ms，总超时20秒。以`chassis/applications/chassis_config.hpp`为准。

路程使用四轮累计角度估计，IMU修正车头方向。轮胎打滑、横向滑移和制动能力不足会产生实际停车误差，2cm是程序切入停车阶段的容差，不是实车定位精度保证。

## 板间通信协议

底盘CAN2发送标准数据帧`0x111`，8字节，任务计划间隔10ms：

| 字节 | 含义 |
| --- | --- |
| data[0] | 右拨杆：0下、1中、2上；遥控失联为0xFF |
| data[1] | 左拨杆：0下、1中、2上；遥控失联为0xFF |
| data[2] | 自动到达且停稳标志：1完成、0未完成或当前运行条件无效 |
| data[3..7] | 当前为0 |

完成标志在上档完成期间持续发送，不是单周期脉冲。云台接收端需要按状态处理，避免重复触发。

云台在`control_task.cpp`检查板间通信是否新鲜，当前阈值50ms。接收无效档位或通信超时后按下档处理。中档时左拨杆上档请求轨迹跟踪；右拨杆上档时，data[2]为1请求跟踪，未置位时执行保持/折叠相关流程。具体机构目标与测距阈值见该文件。

## 功率模型与限制

模型为四轮机械功率、转矩平方损耗、轮速平方损耗与整车静态项之和：

```text
P = Σ(τᵢ × ωᵢ + K1 × τᵢ² + K2 × ωᵢ²) + K3
```

输入为轮侧命令转矩及反馈轮速，K3只对整车加一次。当前K1=4.3、K2=0.013、K3=3.8；这些是经验系数，不等于功率计绝对精度或所有负载下的精度保证。

- PM02上限来自USART6接收的0x0201机器人状态，字段为`pm02.robot_status.chassis_power_limit`；应用层`school_pm02`处理分包、粘包、CRC与13/17字节版本兼容，原中间件不改。
- 实测功率来自CAN1标准帧0x301，电流、电压、功率按高字节在前的16位数除100解析；它不提供比赛上限。
- 当前预测预算为`min(PM02上限,80W)-5W`，额外测试上限已关闭。PM02收到80W时预算75W。
- 预测超预算时，统一缩放四轮转矩；保留条件积分抑制。PM02状态无效或超过1秒未更新，禁止底盘输出。
- 模型内无可行缩放比例时清零转矩，不能据此保证实测功率立即下降到预算。
- 功率计在线状态用于观测，目前未作为与PM02相同的输出联锁条件。

控制任务计划周期1ms、底盘观测发布与发送周期50ms；实际周期受执行时间与调度影响。

## 当前串口输出

通道按`plotter.plot(...)`中实际启用的参数从1开始连续排列；参数旁边的旧编号注释不决定通道位置。采用中间件的二进制帧：AA BB帧头、1字节负载字节数、float32数据。

### 底盘当前启用2通道

`chassis/applications/plotter.cpp`中其余输出被注释，当前是：

| 实际通道 | 数据 |
| --- | --- |
| 1 | 有效PM02上限，W；无效或超时显示0 |
| 2 | 功率计实测功率，W |

因此SerialPlot当前应按2通道配置，不能因为旁边注释写15/18就设为18通道。若要验收展示预测、预算和实测，需要在该文件恢复相应参数并同步调整SerialPlot通道数；本次整理没有改动用户选择的输出。

文件顶部`PLOT_ENABLED`控制是否发送，`PLOT_MODE`选择扩展观测量。恢复完整18通道输出后，顺序为：1—8四轮目标/反馈，9输出许可，10—13模式数据，14功率计在线，15PM02上限，16限制前请求功率，17预算，18实测功率。TORQUE模式显示四轮最终转矩，HEADING显示Yaw/目标/角速度/修正，AUTO_DRIVE显示距离/目标距离/速度命令/状态。

### 云台当前启用7通道

`gimbal/application/plotter_task.cpp`当前依次发送：测距、Pitch命令转矩、折叠命令转矩、Pitch反馈转矩、折叠反馈转矩、Pitch电机角度、折叠电机角度。绘图周期10ms，USART1为921600。

轨迹与评分实现见`trajectory_task.cpp`、`tracking_score.hpp`和`control_task.cpp`。当前启用的绘图参数不包含yaw_ratio/pitch_ratio；如按比赛评分采集，需要切换成规则要求的数据输出并同步通道数。

## 云台与整机验证边界

云台USART6用于GY-56测距，波特率115200。它与底盘USART6接PM02是两块不同板上的接口，不互相占用。

云台目前保留了一些调试状态：电机反馈超时失能及角度限位/恢复检查在部分代码中被注释。不能将“有保护函数或注释”视为保护已启用，正式验收前需由云台负责人核对。先补齐匹配中间件、编译，再联合确认下档能使底盘、Yaw、Pitch、折叠电机全部失能，以及板间断联、折叠/复位、自动停稳后跟踪等行为。

新增或修改运动代码后，先按比赛要求离地或采取等效约束验证，确认方向和失能，再做低速落地测试。命令清零不等于车辆或机构立刻机械停止。
