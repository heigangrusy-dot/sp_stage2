## 底盘程序阅读顺序

代码位于`applications/chassis_task.cpp`，中间件保持原样。任务循环只有四个阶段：

1. `read_input()`复制反馈和遥控输入，`ControlSafety`更新一次下档确认状态。
2. 摇杆死区/限幅、麦轮解算、四路独立速度PID计算。
3. 再读取最新状态，禁止输出时清空PID，统一设置命令、打包并发送。
4. 按20ms刷新曲线，按配置的1ms周期安排下次控制计算。

| 名称 | 职责 |
| --- | --- |
| `ChassisInput` | 本轮输入快照，不把绘图数组当作控制状态使用 |
| `make_speed_pid()` | 统一参数创建独立PID对象，四轮历史状态不共享 |
| `filter_stick()` | 三个模拟输入共用死区和幅值限制 |
| `manual_control_ready()` | 只判断当前手动条件，不修改下档确认记录 |
| `clear_speed_pids()` | 一处清空四轮PID，避免遗漏 |
| `send_motor_commands()` | 设置转矩、四次write填满8字节，再入队一次；返回HAL结果 |
| CAN接收回调 | 检查标准数据帧和8字节长度，按反馈ID更新对应电机 |

所有电机、PID、目标和反馈数组统一使用左前、左后、右前、右后的顺序，分别对应ID2、3、1、4。
`WheelIndex`中的位置索引不等于CAN ID；中间件`write()`会按对象ID选择控制帧字节位置。

配置集中在`applications/chassis_config.hpp`：实际减速比13.7、控制周期、绘图周期、死区、速度尺度和PID参数。
修改编译期常量后需重新构建、烧录。1ms是计划周期，实际执行时间和调度是否满足仍需上机测量。

## 当前保护范围与未完成项

- 上电必须在遥控有效、系统就绪时观察到下档，随后中档才可能允许。
- 四轮反馈超时、遥控失联或CAN状态异常会禁止输出并要求重新确认；有效下档本身不会被反复reset抹掉。
- 发送前复查保留，因为其时间点晚于PID计算；检查和发送不是硬件原子急停，实际响应仍须测量。
- 发送入队失败时清空PID和确认记录，并请求撤销等待中的旧发送帧；后续尝试零命令。
- HAL_OK只代表发送入队，不能证明报文送达。总线故障不能保证零命令到达，动力断电手段仍必须可用。
- 沿用中间件`DBus::is_alive()`，其异常帧有效性问题已提出，尚未修改中间件，也未声称所有输入异常已覆盖。
- 尚未接入板间联动、功率模型/限制和规则要求的整机失能；不能直接把零配置改成大输出落地测试。
- 中间件PID只有总输出和积分输出限幅；正式调试前还需核对规则对各分项限幅的要求。
